Assemble the Frontier from the above in three lists, the kind of each item by its source and no page opened (case 268.2). `## Cases`, what needs a decision: first, when the first line of the `Cases` of the brief's Next session opens with `open the next sprint`, that line (`rule-sprint-close`, case 628.7); then, on a plan branch, the unfinished plan, and each conserved Spec `backlog.md` names, one line each with the source `backlog` — but none while that opening line stands: the session that opens a sprint takes no conserved Spec, which waits in `backlog.md` for the next session (case 632.6); the items of the sprint's current milestone — the first with an open item or with none — and none of a later milestone, of the Backlog or of Closed (case 229.3), and none at all while that opening line stands (case 628.7); the `Cases` list of the brief's Next session; a hand edit shown by `Render:`; a `failed` reading or a lesson of the Tail; an item the person adds. `## Work`, what needs none: the `Work` list of the brief's Next session; a dirty tree in `Status:`. `## Ask`, what only the person can answer: the `Ask the person` list of the brief's Next session, one line per reading with its question (case 531.11). The other items of `backlog.md` are no lines of their own: `## Cases` ends with the line `Backlog: N items`, N the items `backlog.md` counts, and under a Cases line an indented line `- near` names, by slug in a code span, each backlog item whose `purpose` is near that line in meaning — the agent's own judgment from `backlog.md` in its context, no `ask-guppi`; an item the person brings onto the Frontier is a Cases line of its own, source `backlog`, its title opening with its slug in a code span, so that `guppi backlog` counts it (case 451.1). In the chat the Cases are the agenda of Plan Mode, shown as a checklist: each line as `frontier.md` holds it, `- [ ] C<n> — <title> · <source>`, its detail on an indented line under it and the `- near` line under that, the line `Backlog: N items` last; no Case stands as a bold line or with its detail as a paragraph (case 508.2); the Work is one block; sub-cases are cut in Cases only;
the hand edit is what `guppi render --sync` printed at session start or on the `Render:` line above.
A `failed` reading or a lesson in the Tail above is an item; a decision line of the tail is not — its page comes with the next librarian. Write the same three lists, under `## Cases`, `## Work` and `## Ask`, to `vault/raw/<date>/<hi HHMM>/frontier.md` — the session's folder, `HHMM` from the `hi:` line the `UserPromptSubmit` hook put in context (cases 73, 125) — one line per item:
`- [ ] C<n> — <title> · <source>` under `## Cases`, `- [ ] W<n> — <title> · <source>` under `## Work`, `` - [ ] A<n> — `<slug>` — <question> · brief `` under `## Ask`. An item of the sprint's milestone is a line of its own whose title opens with the slug of each page it names, each in a code span — ``- [ ] C1 — `rule-x`, <milestone> · sprint``. Close a line when its item ends, the closer appended and the source kept — `- [x] C2 — <title> · sprint · case 315` (case 314.1). `[x]` is an item ended: `[x] … · case N` when ratified, `[x] … · work` when it needs no decision. `[-]` is an item put off: `[-] … · sprint · defer` when the item is a line of the sprint page left for a later session — no Case, no ledger line, no `deferred_by`, never `· defer case N` (cases 310.5, 356.2); `[-] … · backlog · kept` when an item of `backlog.md` is left as it stands — no Case, no ledger line, it stays in the backlog; `[-] … · defer case N` when a decision of any other source is put off — a short-form Case and its ledger line, and its target enters `backlog.md` through `deferred_by` (case 451.1), or a Case of the conserved Spec the session takes, as below (case 620.1); an item the person adds is a new Cases line; a `W` that turns out to need a decision closes `· case N`, a `C` that needs none closes `· work`. `/pre-spec` fails on an open line under `## Cases`, not on one under `## Work` or `## Ask`; a `W` or an `A` line closes `· work` when its work is done, where it is done: at `/hi`, in Work Mode or at Retro (cases 356.1, 508.2). Claude Code's plan mode does not stop this: the agent writes `frontier.md` and closes its lines while plan mode is on — a working file of the session (`rule-permissions`, case 363). Before the question on the order, in the same reply, take each reading of an open `W` line whose whole method can be done now: each moment its `method` names is this `/hi` or has come in an earlier session (case 613.2). Read what the method names from the brief, `git log`, `git status` and the commands the method names, and each moment of an earlier session — the librarian's run, `/retro`, `/handoff` or any other — from the transcript of the latest session that held it: the event logs `vault/raw/<date>/event_log.md` name each session by the first characters of its id, and its transcript is the file of Claude Code whose name opens with that id; read each part of the method from the session where its moment came. The Frontier is still assembled with no page opened; this step opens the page of each Estimate it reads and judges the reading against its `## Criterion`. Close those lines `[x] … · work` in `frontier.md` first, then write the reading lines in a `LEDGER` block of the reply, which ends in text. A reading with a moment that has come in no session yet, or whose transcript Claude Code no longer holds, waits for its next moment, and its line stays open; a reading whose `method` asks for a `/hi` run of its own is not taken here (cases 508.1, 613.2). Then put each open `A` line to the person as a question, in the same reply, before the question on the order: the Estimate by slug and its question. When the person answers one, close its line `[x] … · work` in `frontier.md` first, then write its reading line in a `LEDGER` block of the reply, which ends in text, the answer as its result (case 531.13). Wait for the human to pick the order or defer items. Every Case is built by `case-guppi` (`rule-case-build`). A conserved Spec on `## Cases` is taken whole and run by `/box` (`rule-spec-box`, case 591): take it only while the session's ledger holds no decision line other than a `defer`, and ratify no Case after it but a short-form defer; close its line `[x] … · work`; create the plan file with one title line, `# Session <hi HHMM> — runs the conserved Spec vault/raw/<date>/<HHMM>/spec.md`, the path `backlog.md` names; close the other open lines under `## Cases` as left — a line whose target a `defer` item of that Spec puts off closes `[-] … · defer case N`, N being the Case of that Spec that holds the item, with no short-form Case and no ledger line of this session (case 620.1) — and go on to `/pre-spec`.
