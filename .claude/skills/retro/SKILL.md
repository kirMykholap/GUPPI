Retro is an analysis of this session for the librarian and the next session, not planning, and it runs without the person: `/work` calls it in the same turn, and you stop only on a condition of `vault/wiki/where-to-stop.md`, which `/work` loaded (case 531.1). Show no report and ask for no approval. Read `vault/raw/<date>/<hi HHMM>/work.md` when it stands, which `/work` wrote (case 479.3): when you wrote or changed it yourself in this turn, the text you hold counts as read; otherwise open it with the Read tool (case 569.2). When `work.md` holds `## Conserved Spec`, this session runs that conserved Spec by `/box`, and builds it: below, the Spec of this session is the `spec.md` of the folder that section names, and the decision lines of that folder's `ledger.md` count as lines of this session's ledger — for the boxes, for the scope of an edit and for the readings of the Estimates this session creates or updates; the ledger hook sees only this session's own lines (cases 591, 670.2). Sort the unticked boxes of the `tasks` of the Spec — `raw/<date>/<hi HHMM>/spec.md` in the session's folder (case 73), or the `spec.md` of the folder of `## Conserved Spec`. A `create`, `update` or `defer` line of a page, a `guppi render` line, a `guppi sprint` line, a `guppi sprint-close` line, as `rule-sprint-close` names it (case 628.1), a `read` line whose `estimate[...]` stands in the Tail above and a `read` line whose reading you take in this turn wait for the librarian, whose scripts tick them (cases 226, 250, 270); they are not debt. A `read` line whose `failed` line you write in this turn waits for the librarian as a reading does. A `read` line of an Estimate whose reading only the person can take, named under `## Ask the person` of `handoff.md`, waits for the person; it is neither debt nor the librarian's (case 670.2). Another `read` line without its line in the Tail is debt, and so is a box of code, a test, a command or a migration left unticked. The lines of a Case that a `{supersedes:case N}` line of the Tail names, and of its sub-cases, are not counted at all; its work stands under the superseding Case (case 282).

Each finding ends in one of three ways: a `- lesson[...]` line, which you decide on; a `- estimate[...]` line, a reading of an Estimate whose work is finished; or a line of `handoff.md` in the section of its kind, which `/handoff` writes. Retro writes no short defer and ratifies no decision: what needs a decision is a line of `## For the next session` of `handoff.md`, and a `create`, `update` or `delete` waits for the next Plan Mode (case 531.1).

Edit code only when the edit finishes work that traces to a line of this session's ledger.
Red tests: fix now when the fix finishes ratified work; otherwise save the change with `git diff` into `raw/<hi date>/<hi HHMM>/patch-<slug>.diff`, the session's folder, revert it, write a `- lesson[error][...]` line whose root cause says why Retro was reached with a regression, and name the patch in `## Debt` of `handoff.md`; the commit still needs green. A failing test or a lint finding line that `## Baseline` of `work.md` already holds was red before the work, whatever `## Expected red` names: it is a line of `## Observations` of `handoff.md`, named as red before the work; it is not debt, nothing is fixed or reverted for it, and no lesson is written for it (case 479.4).
`gh` is not available: name a bug that needs a decision in `## For the next session` of `handoff.md`, so the brief carries it.
Do not run `uv run --project .guppi guppi check` here: the vault is written after handoff, by the librarian. A check that reads a page or a governed file this session's Spec updates — `uv run --project .guppi guppi check` or one of its steps, or a hook of the working tree — is red or refuses in Work Mode until the librarian's run writes the page or renders the file, and the `uv run --project .guppi guppi check` of that run is its reading: `/work` marks such a red under `## Expected red` of `work.md` when the task that changes the check runs, one line naming the check and the page or file it waits for. A red or a refusal of that check on a page or file a line names is a line of `## Observations` of `handoff.md` that names the check and the page or file it waits for, and it is not debt; a red or a refusal on a page or file no line names is debt, even when another line names the same check, unless `## Baseline` holds its line. In a session with no `work.md`, such a red is a line of `## Observations` by your judgment. A red test is never an expected red: it is fixed or reverted as above (cases 473.1, 479.3).

Take the readings of the Estimates whose work is finished and that this session neither creates nor updates — by a decision line of its slug, or by an `update` that renames a page to it. A reading measures the Criterion the page carries at the moment of the reading, the one ratified last, and its line is written only when the work that Criterion names is built. Read each Estimate this session creates or updates — by a decision line of its slug, or by an `update` that renames a page to it — in this turn, on the Criterion of the Spec: the `when` and `then` of its Case, or the Criterion its item writes; the ledger hook writes such a reading only after Retro opens (cases 670.1, 670.2). For an Estimate of a rule whose Render a Case of the Spec changes, read the new text of the Render in the Spec against that Criterion: the harness file follows at the librarian's render, and its `uv run --project .guppi guppi check` checks the file. An Estimate whose `update` sets `passed` or `failed` by the person's decision and writes its Criterion back unchanged, and one whose `update` names one part of the page alone, is neither read nor set `failed`. The `read` line of an old Criterion in an earlier Spec is not debt and is not read (case 283). An Estimate whose `target` is the live sprint page, `entity-sprint-<id>`, and whose work is not done yet is neither read, nor put to the person, nor set `failed`: it stays `pending` for the Retro of the session that finishes its work or for the closing Case of `/sprint-close`, its `read` line waits for that moment and is neither debt nor the librarian's, and `handoff.md` names it with that moment; once its work is done, the Retro of that session reads it, or, when its `method` names the person's answer, names it under `## Ask the person` as below (case 772.2). An Estimate this session creates or updates whose `method` waits for an event — a part of it that opens with `after`, or with `by hand, after`, and names the event before a colon — and whose event has not come in this session is neither read, nor put to the person, nor set `failed`: it stays `pending`, its `read` line waits for that event and is neither debt nor the librarian's, and `handoff.md` names it with its event; once the librarian sees the event, it puts the reading under `Work`, or under `Ask the person` when its `method` names the person's answer. When the event came in this session, read it (case 781). A reading whose `method` names the person's word is not yours to take: it is a line of `## Ask the person` of `handoff.md`, with the question the person answers (case 531.1). Each other Estimate this session creates or updates that you cannot read gets a `failed` line in the same `LEDGER` block, its result opening with the date, the words `Retro, not read` and the reason; the next session shows it as a Case.
