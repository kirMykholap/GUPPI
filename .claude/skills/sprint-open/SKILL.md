---
name: sprint-open
description: "Open the next sprint. Run it when the hook on /hi says that no sprint is open, or when the person types /sprint-open."
---

No sprint is open: the first heading of `vault/wiki/sprint.md` marks the last sprint closed. This session opens the next one. The ledger hook refuses each decision line but a `defer` until a `create` of a page `entity-sprint-<id>` stands, so the opening Case is the first Case the session ratifies. It also refuses that `create` when a live or archived sprint page already holds the id: ask the person for another id, and send the opening Case back to its `case-guppi` to be built again under it.

1. Assemble no Frontier yet: the opening Case comes first, and no other item of the session is taken up before the person ratifies it.
2. Ask the person first, in one plain question, for the id of the sprint, which names the page `entity-sprint-<id>`, the branch of the sprint and every Case id of the sprint: it starts with the GitHub name of its author, such as `kir-plugin`, and holds lower-case letters, digits and hyphens and no dot. Then dispatch `case-guppi` at once for the line `open the next sprint` of the brief, as `vault/wiki/orchestration.md` sets it, with the Case id `<id>-1` and the id of the sprint, and write into the prompt of the call that the opening Case asks the person, in its rounds:
   - its goal in one sentence, the `purpose` and the `## Purpose` of the page;
   - its Definition of done, one Estimate per condition, which the page lists in `estimates`;
   - the first milestone and its items, under `## Milestones`;
   - whether to take any item of `vault/wiki/backlog.md` into the sprint: the Case says how many items the file holds, and goes through no item the person does not name.
3. Write into the same prompt that the opening Case writes, as the last two items of the last milestone of the page, the line ``- the merge of `main` into `<id>` — `/merge-main`, a session of its own`` and then the line ``- the close of `<id>` — `/sprint-close`, a session of its own``, so that `/merge-main` runs before the close and the session that closes the sprint starts `/sprint-close` from the close line.
4. Write into the same prompt the branch that `/hi` printed under `Branch:`, and whether the person is the owner of the repository: the login that `gh api user --jq .login` prints is the one that `gh repo view --json owner --jq .owner.login` prints. When the branch is not `main`, the closed sprint ran on it, and the opening Case holds as its first task lines, in this order, `<id>` the id of the new sprint:
   - for the owner, one task line that opens with `stop:` and runs `git push -u origin <branch>`, `gh pr create --base main --fill`, `gh pr checks <branch> --watch` and `gh pr merge <branch> --merge`, which push the closed branch, open its pull request into `main`, wait until its checks pass and merge it with a merge commit, never with `--admin`; then `git fetch origin`, `git switch main`, `git merge --ff-only origin/main`, `git switch -c <id>` and `git branch -d <branch>`, so that the local `main` follows `origin/main`; no Case reviews this pull request, since each change of the closed sprint was ratified in its own session;
   - for an author who is not the owner, one task line that opens with `stop:` and runs `git push -u origin <branch>` and, when `gh pr view <branch>` shows no open pull request, `gh pr create --base main --fill`; then `git switch -c <id>` and `git branch -d <branch>`, so that the branch `<id>` starts from the closed branch and keeps its work until the owner merges the pull request by `/pr-review`.

   The Spec holds the opening Case first, so Work Mode runs them before any other task, and the rest of Work Mode runs on the branch `<id>`. Work Mode stops before the task line that opens with `stop:` and runs it after the person's word. The opening Case does not merge `main` into the closed branch: `/merge-main` did so before the close. A refusal of a `git` or `gh` command of these tasks, `gh pr checks --watch` on a red check and `gh pr merge` on a pull request that cannot be merged among them, is a stop on the sixth condition of `vault/wiki/where-to-stop.md`. When the branch is `main`, the opening Case holds no merge, branch or deletion task: Work Mode stops on `main`, and goes on after the person makes the branch `<id>` and moves to it. The opening Case puts no question on the merge or the branch to the person.
5. The skill decides none of the answers: the main agent asks the person for the id, and `case-guppi` puts each other question to the person, and the person ratifies the opening Case as any other. Before the reply that acknowledges it, assemble and write the Frontier as `/hi` sets it, the items of the first milestone of the opening Case among its Cases; that reply shows it, as `vault/wiki/orchestration.md` sets that reply.
