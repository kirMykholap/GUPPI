# What happened, 2026-08-21

**The rule is to write a miss into `.superpowers/sdd/vault-feedback.md` in the same turn it
surfaces, and never to carry it** ([[write-the-miss-into-vault-feedback-before-the-turn-ends]]).
**It met plan mode in four consecutive turns and lost in all of them.** Every line was drained the
moment plan mode ended, so nothing was lost — but the property the rule exists for, that the record
does not depend on remembering, did not hold.

# It is recorded as one defect and not as four lapses

**The obligation sits on the session, and the session is the party plan mode disarms.** Writing is
exactly what plan mode forbids, and the rule requires a write at the moment of noticing. Counting
this as four instances would file it under diligence, which is the wrong drawer
([[knowing-a-rule-is-not-a-mechanism]]).

**`/pre-task`'s own `record-pre-task.ps1` has the identical shape and the identical hole**, already
recorded as a known gap in its skill. The two are the same defect met from two directions
([[the-ritual-records-itself-rather-than-being-detected]]).

# What follows from it, and it is already the argument for something

**A hook can write during planning and a session cannot.** The ledger rows carrying `plan` in their
permission-mode column are the proof, and the same observation is the ground for putting a
`PostToolUse` hook that writes the row ahead of any blocking gate
([[plan-mode-blocks-edits-and-not-a-subagent-dispatch]],
[[one-ledger-is-the-record-the-heartbeat-and-the-permission-mode]],
[[a-pre-task-agent-and-a-post-tool-use-hook-that-writes-its-row]]).

**Nothing is decided here about moving the obligation.** The alternatives — a hook that records, a
transit file the mode permits, or leaving the rule and accepting the drain at the end of plan mode —
are the owner's, and no design was put to him ([[a-question-asked-is-not-a-question-answered]]).

# The citation is repointed, and the gap it pointed at is not recorded at the new address — 2026-08-22

**`sources:` cited `.claude/skills/pre-task/SKILL.md` and now cites `.claude/agents/pre-task.md`**,
because the skill was deleted on this date ([[the-pre-task-becomes-an-agent-and-the-ritual-is-enforced]])
and rule 5 of the gate requires every repository path in `sources:` to resolve — a citation to a file
that is not there reads as provenance and is not ([[vault-scripts]]). **The address moves and the
history stays readable**: this page was compiled while the skill existed.

**What it was cited for did not survive, and the sentence above is dated rather than corrected.**
*"`/pre-task`'s own `record-pre-task.ps1` has the identical shape and the identical hole, already
recorded as a known gap in its skill"* — the skill carried that gap in its own words, under the
heading *Known gap: in plan mode this recording cannot happen*. **`.claude/agents/pre-task.md`
records no such gap**, and it does not because the gap is closed on that side: the row is written by
`.claude/hooks/record-the-dispatch.ps1` on `PostToolUse`, and a hook can write during planning
([[the-dispatch-record-hook]], [[plan-mode-blocks-edits-and-not-a-subagent-dispatch]]). The agent is
told in as many words not to write the row itself.

**`scripts/record-pre-task.ps1` is still in the tree**, so the shape this page compared itself to
still exists; what changed is that the ritual no longer depends on it.

**This page's own subject is untouched by that repair.** The miss-recording obligation still sits on
the session, plan mode still forbids the write, and nothing has been decided about moving it — which
is what the section above says and what remains open ([[write-the-miss-into-vault-feedback-before-the-turn-ends]]).

# The sixth and seventh instances, and what is new is that the answer now has a known shape — 2026-08-23

**Two misses were found inside plan mode and carried in the session's head from morning until plan
mode ended.** Both were written the moment it did, so again nothing was lost and again the property
the rule exists for did not hold. **The cause is unchanged**: writing is what plan mode forbids, and
the rule requires a write at the moment of noticing.

**The rejected alternative was to obey**, and this time it is recorded as having looked *impossible*
rather than *unnecessary* — which is the distinction that separates this from diligence and keeps it
out of that drawer ([[knowing-a-rule-is-not-a-mechanism]]).

**What is new since 2026-08-21: a hook writes during plan mode, observed with a real ledger row.**
That was the argument for putting the dispatch record on `PostToolUse`, and it has since been built
and is running ([[the-dispatch-record-hook]], [[plan-mode-blocks-edits-and-not-a-subagent-dispatch]]).
**So the deadlock has a known shape of answer that nobody has applied to this rule** — the same
mechanism, pointed at `.superpowers/sdd/vault-feedback.md` instead of at the ledger.

**Still nothing is decided about moving the obligation**, and this page does not decide it. The rule
is one of the five the owner ruled must each get a mechanical instrument, and this recurrence is the
evidence for what that instrument has to survive
([[every-rule-in-wiki-rules-owes-a-mechanical-instrument]],
[[write-the-miss-into-vault-feedback-before-the-turn-ends]]).

# The eighth instance, and the hook that would answer it is deferred by name — 2026-08-23

**The count reached eight, always for the same reason.** The feedback rule asks for a `- miss:` line
in the turn it is noticed; plan mode disarms the party the rule binds, and the lines are carried to
the end of the session instead.

**The owner deferred the hook that would write the line, and named when to raise it again:**

> **owner: напомнить об этом в следующей сессии**

**The consequence has a second edge now.** This hook would give one of the six instrument-less rules
its instrument, which is acceptance criterion 1's subject
([[every-rule-in-wiki-rules-owes-a-mechanical-instrument]],
[[write-the-miss-into-vault-feedback-before-the-turn-ends]]) — so the deferral is no longer only
about the feedback loop, it is about a criterion the sprint is decided by.
