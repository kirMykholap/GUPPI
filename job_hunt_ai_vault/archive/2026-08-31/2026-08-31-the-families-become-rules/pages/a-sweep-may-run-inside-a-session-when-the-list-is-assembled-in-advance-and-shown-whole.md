# The change, 2026-08-24, and it is the owner's

**The condition replaces the calendar.** The page this replaces ruled that the sweep waits for a
session of its own and rejected *"doing it today, at the end of a session that had already spent
itself."* What that rejection was protecting is now stated as the condition it was protecting:
**the list is assembled before the conversation starts, and shown whole with each block's context.**

**A sweep meeting that condition may run inside any session.** One that does not still waits, and
lifting that is a conversation with the owner rather than a session's call.

**Rejected: keeping the session-of-its-own rule.** It was written against a real failure — blocks
read consecutively are read carelessly by the tenth — and the failure it names is about
*preparation*, not about which session the clock says it is. The sweep of 2026-08-24 ran inside a
build session, with the list assembled first, and it worked.

# What the run itself is evidence of

**Of everything shown to him, he rejected exactly the block with a drifted number sewn into it.**
That is not proof the condition is sufficient, and it is the only reading available: careless
consent would not have found that one.

**And it is recorded as a divergence as well as a change**
([[divergence-the-ratification-sweep-ran-inside-a-build-session]]). The rule was broken before it
was changed, and the outcome is not what makes the break legitimate.

# What carries over from the page this replaces, unchanged

- **The whole sweep is the owner's and not the librarian's.** Only he can separate a faithful
  paraphrase from a wrong one
  ([[the-retro-records-a-ruling-chosen-from-a-menu-and-ratifies-decisions-not-utterances]]).
- **The list is read from the run, never from a page.** `bash scripts/vault-check.sh --lint` names
  the blocks carrying no Cyrillic, one `path:line` per line. A figure written here would be the copy
  that drifts ([[a-drifting-list-is-repaired-by-deleting-it-not-extending-it]]).
- **What to do with a block he upholds is still written in a skill and in precedent, and in no
  decision page.** The predecessor named that gap and did not close it; neither does this. The
  ratification of 2026-08-24 was taken over a list rather than block by block, so it does not settle
  it either ([[the-ratification-is-one-decision-over-a-shown-list-and-not-a-signature-per-block]]).

# *The list is read from the run, never from a page* is wider than the reason under it — 2026-08-26

**What that clause forbids is a standing figure in the corpus** — a count or a roster written onto a
page, which goes false as the tree moves and which nothing re-derives. Its own reason says so: *a
figure written here would be the copy that drifts*.

**It does not forbid freezing a working list for one run**, which is the condition in this page's own
title. A list assembled in advance, shown whole and used inside the session that assembled it cannot
drift: it is discarded when the run ends.

**Without this line the next `/pre-task` reads a live breach, and the breach is not there.** The
overturn of the alphabet test orders *freeze the list, run the sweep, then overturn*, and says **the
list is frozen by page and claim, never by line number** — citing this page for it
([[the-alphabet-test-behind-the-owner-block-advisory-is-overturned]]). Read against the clause above
taken at its widest, that is a live `prohibition` contradicted by a live decision that cites it; read
against the reason under the clause, the two agree and always did.

**The freeze exists because the instrument is being withdrawn.** `--lint`'s advisory is today the
only index of which owner-attributed blocks the ratification of 2026-08-24 ranged over, the sweep
destroys that index as it rewrites, and the predicate behind the advisory is cancelled. **So the run
that would produce the list will not exist when the sweep needs it**, which is exactly the case the
clause was not written about ([[a-clean-run-cannot-test-an-advisory-exemption]]).
