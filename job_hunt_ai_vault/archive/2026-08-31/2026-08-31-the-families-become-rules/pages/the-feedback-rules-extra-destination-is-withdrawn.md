# What was approved, and then withdrawn the same day

**The owner approved it**: «4) да» — `.superpowers/sdd/vault-feedback.md` becomes another `governs:`
address of the feedback rule, so the instruction has one copy and every file that restates it is
rendered from that copy.

**`/pre-task` killed it.** The vault already holds a page written because a previous `/pre-task`
killed the same proposal: the file is git-ignored and `/handoff` empties it every session, so the
injector reports a destination carrying no region, exits 1, reddens rule 12, and
`lock-the-librarian.ps1` reads a red gate as a refusal to dispatch — locking out the only writer who
could clear it ([[a-rule-may-not-govern-a-file-the-ritual-empties]]).

**The plan was revised against the finding and the address was dropped.** What replaced it is a
destination that is not emptied ([[the-owner-block-rule-gains-the-repository-claude-md-as-a-destination]]).

# The session also named the wrong mechanism for its own proposal

**It claimed rule 12 would guard the agreement.** Rule 12 guards a region against the page that
renders into it, and under this proposal there would have been **no region** — the file is emptied
before the check ever reads it. The mechanism named and the mechanism that fires were different
things ([[a-check-asks-by-running-the-writer-it-checks]]).

# What is left standing

**The defect the address was meant to close is still open.** The verbatim obligation on a
`decision:` mark exists in `.superpowers/sdd/vault-feedback.md` alone, which sits outside the
governed sweep, so the rule's own renderings do not carry it
([[a-mark-that-names-the-shape-of-a-decision-is-not-obliged-to-carry-the-words]]).
