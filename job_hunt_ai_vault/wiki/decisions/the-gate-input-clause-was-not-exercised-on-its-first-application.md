# The divergence, recorded 2026-08-19

**What the rule says:** what the gate reads as its own input is the session's to write **and the owner
reads the diff before the commit**
([[what-the-gate-reads-as-its-own-input-is-the-sessions-to-write]]). The read diff is not decoration:
it is one of the two properties the clause states **instead of** the paperwork it replaced.

**What was done:** the owner approved *committing*, having been shown only the selftest's code diff,
and the commit followed — carrying the clause's own text and the six schema comments, which he had
not read.

**Rejected: showing him the vault diff and waiting**, which is what the clause says.

# Why it looked unnecessary

His *"commit and ritual"* read as covering the whole tree, and **the clause was two hours old and not
yet a habit**. A rule taken in the same session it is first applied has no muscle memory behind it,
and the reviewer and the reviewed were the same conversation.

# Remedied inside the session, and the remedy is not the property

**The text was put to him afterwards and ratified unchanged** — the A1 clause's wording and the schema
comments both stand as written.

**But the property the clause names was not exercised at the moment it names it.** *Ratified after the
commit* and *read before the commit* are different facts, and only the second is what makes an
out-of-band write safe ([[hand-edits-of-the-wiki-are-a-recorded-divergence]],
[[the-one-writer-rule-covers-the-registers-too]]). The clause survives its first application on the
strength of a review that happened in the wrong order.

**It is recorded rather than waved through** because a clause whose first application diverged from it
is exactly the one a later session will cite as precedent
([[a-licence-cited-where-none-was-needed-is-named-so-it-is-not-inherited]]).
