# The exclusion, 2026-08-20

**A write into the vault does not arm the pre-task net**, whichever vault path class the payload
names — the guard already knows them all, and every one of them is excluded.

**Two reasons, and each is sufficient.** The librarian writes only the vault and writes about fifty
pages per ingest, so the net would fire on the one agent it is not addressed to, dozens of times per
run ([[the-librarian-writes-unattended]]). And **a vault write is not implementation**: the ritual
asks whether a plan has been checked against the corpus, and the party writing the corpus is the
answer rather than the question ([[vault-librarian]]).

**Rejected: letting the net fire and relying on `once per session` to bound it.** Once per session
is one spurious advisory per ingest into the context of the agent least able to act on it, and an
alarm that fires when nothing is wrong is one you learn not to read
([[an-alarm-that-fires-when-nothing-is-wrong-is-one-you-learn-not-to-read]]).

# What it does not do

**It does not exempt a session from the ritual because it is writing the vault by hand.** The
exclusion is about which payloads arm a hook, not about which work needs checking — a session that
edits `wiki/` under an owner's authorisation is covered by that authorisation and by nothing here
([[the-session-wrote-wiki-by-hand-while-the-lock-held-its-only-writer-out]]).
