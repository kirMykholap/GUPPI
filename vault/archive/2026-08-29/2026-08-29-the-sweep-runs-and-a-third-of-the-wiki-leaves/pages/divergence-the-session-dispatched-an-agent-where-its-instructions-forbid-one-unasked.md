# Two rules, and they contradict

**`/pre-task` may be performed only by dispatching the `pre-task` agent** — the ritual sits between
the plan and its approval and there is no other way to perform it
([[the-pre-task-becomes-an-agent-and-the-ritual-is-enforced]],
[[the-pre-task-always-dispatches-its-narrow-phase]]).

**The session's own instructions forbid calling an agent the owner did not ask for.**

**A session that reaches the ritual must break one of them.** There is no order of operations in
which both hold.

# What was done, and it is the one part that was right

**The session did not resolve it silently.** It put the contradiction to the owner and asked.

> **owner:** «да, запускаем.»

**Rejected: dispatching quietly and recording it afterwards**, which is what makes a divergence
expensive — the owner learns about the departure from a journal instead of from a question.

# The contradiction stands for the next session

**Neither rule was changed and neither was marked as losing.** The authorisation was for that
dispatch, on that day; the next session meets the same fork with the same two rules
([[a-question-asked-is-not-a-question-answered]]).

**Deciding which of two rules is the real one is a judgement about the project**, and it is not the
librarian's to take either.

# The fork was resolved on 2026-08-25

**The contradiction this page left standing has an answer**, and the answer is dispatch: the ritual is
performed by dispatching the agent, and the rule forbidding an unasked dispatch is the one that is
wrong as written ([[the-pre-task-is-performed-by-dispatch-and-the-unasked-dispatch-rule-is-the-wrong-one]]).

**This page is not retired by that.** It records what happened on the day it happened. What changed is
that no session after it has to break a rule to run the ritual.

**Nothing in the harness was edited**, so a session reading the two instructions today still finds both
sentences as they were.
