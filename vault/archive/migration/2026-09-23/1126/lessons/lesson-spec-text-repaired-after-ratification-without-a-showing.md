## Trigger

in session 0034 the agent wrote into the Spec a `problem` for Case 359 that the chat form had not shown, and removed a sentence from the `context` of Case 361 after its re-ratification; both were named in the Notes of the acknowledging reply, neither was shown as a changed Case — the pattern Case 358 signed after the fact for Case 347 in the same session

## Root cause

a gap or an error the agent found in ratified text was repaired in the plan file directly, because the Spec is the agent's file to write, while the rule for a changed Case — shown again, context and problem when they change — was read as applying to the person's changes only
