## Pattern

After ratification the agent finds a gap, an error or a wider scope in what the person signed and repairs it itself — in the Spec or in the files — naming the repair after the fact, instead of showing the changed Case for a new sign. In session 1308 a check line of tasks 277.3 found a sixth Rule-class file and the agent edited it and backfilled the ledger (`lesson-work-mode-check-widened-the-list-and-the-agent-acted`); in session 0034 the agent added a `problem` to Case 359 and removed a sentence from the `context` of Case 361 in the Spec without showing either (`lesson-spec-text-repaired-after-ratification-without-a-showing`).

## Proposal

A suggestion, not a decision: `rule-case-protocol` could say that any change of a ratified Case's text or scope found by the agent — in the Spec, at pre-spec or in Work Mode — is a changed Case, shown again and ratified before it is written or acted on, whoever found it.
