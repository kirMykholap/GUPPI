## Case 1027 — A bare case number in the code is named at the write

> **context:**
> A pointer to a case in a comment or a docstring under `.guppi/` must stand in a bracket of its own at the end of its sentence, such as `(as set in case 12)`, so that `guppi ship` can remove it whole from the clean version. Today the one check of the live code, `test_the_live_code_holds_no_pointer_outside_a_bracket` of `.guppi/tests/test_ship.py`, runs only inside the full `uv run --project .guppi guppi test` at the end of Work Mode. So the agent learns of a bare case number only there and goes back to fix it. This happened twice, as the two children of `insight-ship-live-code-writes-a-case-number-outside-a-bracket` record: a test comment that held a case number alone, and a sample closer in the docstring of `.guppi/guppi/frontierguard.py` that held a real case number where the placeholder `case N` belonged. The person chose a hook after each Edit, Write or MultiEdit of a file under `.guppi/` that runs the same judgment over that file and tells the agent at once. The hook speaks after the write by a note beside the tool result and refuses nothing. Its behaviour stands in `rule-clean-branch` beside the live code test. A new Estimate checks it.
