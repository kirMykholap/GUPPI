## Case 1079 — A trial of Code Mode in a clone of the project

> **context:**
> Code Mode is an experimental mode of Claude Code. In it, Claude writes a short JavaScript program that makes several tool calls in one step, and Claude Code runs that program. The page https://code.claude.com/docs/en/code-mode.md says that it runs only in an interactive `claude` session in a terminal, not in the VS Code panel. It needs v2.1.323 or later and the variable `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE` set to `1` in the shell or in `~/.claude/settings.json`, and Claude Code ignores that variable in the settings of a project. A session started in Code Mode resumes only with Code Mode on. A subagent with a `tools` list uses Code Mode only when `REPL` is on that list. The same page says that `PreToolUse` hooks and permission rules control the calls made inside the code under the tool's usual name. It also says that a `PreToolUse` hook that fails in a way other than a timeout lets the call go on unless the hook sets `onFailure: block`, and no hook of `.claude/settings.json` sets `onFailure`. The page does not say whether `PostToolUse` hooks run on those calls, or whether a hook that rewrites the input of a call reaches a call made from code, and it gives no figure for tokens or time. The first part of https://code.claude.com/docs/en/hooks.md mentions Code Mode only to point to that page for timeouts. Every guard of the harness is a hook on a tool call, so the trial asks whether they answer a call made from code. No live text of the vault or the harness speaks of Code Mode. The person chose a clone outside the repository, a trial in Work Mode of this session, and a read-only task for the measurement.
>
> Choices of form. The trial has two promises that can fail apart, the cost of Code Mode and the answer of the hooks, so it is two sub-cases with an Estimate each. Each Estimate is a one-off Research Estimate of the live sprint page `entity-sprint-plugin` with `once: true`, since its `method` reads the transcripts of sessions (case 1071.1). Its `method` waits for the person's word that the sessions ran, so the Retro of this session takes the reading once the word stands and leaves it `pending` before that. The hook check runs in a third session, so its calls do not enter the counts of the two measured sessions. The task of 1079.1 builds the environment of the clone's hooks by `uv sync` before the first session, so the first hook of the trial does not build it within its timeout of 30 seconds. The clone is a write outside the repository, which git in this repository cannot undo, so a `stop:` task waits for the person's word before the agent makes it, by the third and fourth conditions of `vault/wiki/where-to-stop.md`. That task waits for a word before a command, so it gets no line `**From the person:**` (case 1077.1). The finished file of Case 1077 keeps that `－` line in 1077.1. Its 1077.2 closes the Frontier line of an action on the person's word that it is done, and each stop task of this Case that waits for the sessions ends with that word. The clone stays after the trial, since its deletion is a deletion outside the repository, a stop by the same third condition. The clone carries `.claude/settings.json`, which sets `"defaultMode": "plan"`, so a bare `claude` there starts in Plan Mode, where Claude may answer with a plan rather than the list. So both measured sessions start in one named mode, by `claude --permission-mode default`. The hook session starts by `claude --permission-mode acceptEdits`, so that Plan Mode does not refuse the edit before a hook does. In default mode, Claude Code may ask before a Bash call. The seconds that `guppi agents` counts include the time the person takes at such a prompt, so the person answers each prompt at once. A Case of a later session changes the harness for Code Mode, by the finding, as the person asked. The one rule of `rule-ratification` holds: the clone is outside the repository, so a call that no hook stops changes only the clone.
>
> The frame. `lines_of`, `calls`, `tool_calls`, `seconds` and `run` of `.guppi/guppi/agents.py`, and `call_size` of `.guppi/guppi/context.py`, were read whole. The line of the main agent gives its calls, its tokens, its tool calls and the seconds from the first record of the transcript to the last. Its tokens are the sum, per call, of the input, cache read, cache creation and output tokens of `USAGE_KEYS`. `tool_calls` counts the `tool_use` blocks of the assistant records, and whether a call made from code stands as such a block was not checked. The expected answers of the hooks come from these functions, read whole. `run`, `governed` and `relative` of `.guppi/guppi/guard.py` refuse an `Edit` of `CLAUDE.md`, whose `governs` field is on `rule-claude-md`, and write a line to the event log. `run`, `refusal`, `heredocs` and `file_write` of `.guppi/guppi/bashguard.py` refuse a heredoc whose marker line writes a file, and write a line too. `before`, `searched_folder` and `guarded_glob` of `.guppi/guppi/grepguard.py` add `!**/decisions/**` to the glob of a Grep over `vault/wiki/`. `before`, `after` and `page_of` of `.guppi/guppi/pageread.py` cut a whole `Read` of a page before its `## History` and add a note after it. `run`, `format_line`, `tool_detail`, `log_path` and `project_root` of `.guppi/guppi/event.py` write one `tool` line per call into `vault/raw/<date>/event_log.md` of the project in `CLAUDE_PROJECT_DIR`. A Grep `^type: decision` over `vault/wiki/`, with the hook's exclusion, printed one file, `vault/wiki/rules/rule-decisions-schema.md`, so a Grep from code that prints a path under `vault/wiki/decisions/` shows the rewrite missing. A Grep `Code Mode|code-mode|CODE_MODE|\bREPL\b` with the glob `{vault/wiki,.claude,.guppi/guppi}/**` printed no file, and a Glob `vault/**/*code-mode*` printed nothing, so both new slugs are free.

Of the Estimates of `entity-sprint-plugin`, none has a `purpose` that speaks of Code Mode. `estimate-sprint-plugin-case-guppi-level-trial-decided` speaks of the time and tokens of the levels of the dispatch of `case-guppi`, and `estimate-sprint-plugin-retro-loads-in-the-cli` of `/retro` in the CLI, so both stand. The Purpose of the sprint page says that the sprint is done when every Estimate passes, and a one-off one by one reading that passes. Its list after that names the main deliverables and claims no full list, so it stands with the two new Estimates. The clone lies outside the repository, so no folder of the repository holds it, and no reader of the repository's folders or `.gitignore` takes it. The Case changes no live file of `vault/` or `.claude/` and no check, so no test of `.guppi/tests/` reads a changed text. The session's ledger holds no `error` lesson.

> **problem:**
> Code Mode may save tokens and time, but no figure shows it for our work. The harness rests on hooks, and the documentation does not say whether all of them answer a call made from code. A trial in this repository could change pages or harness files with no ratified Case wherever a hook does not fire.
