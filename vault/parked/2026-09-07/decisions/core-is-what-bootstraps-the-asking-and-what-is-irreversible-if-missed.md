# The owner's criterion, 2026-08-18

> **owner: Core is a decision, not a summary.**

**The repository's `CLAUDE.md` carries what bootstraps the asking** — the rules a session needs
*before* it can reach the vault at all — **plus what is irreversible if missed.** Everything else is
a page that a question reaches.

**It is a criterion rather than a taste, and it was tested as one:** it sorts all nine rules of that
file without a remainder. That is the property a criterion has to have before it is worth writing
down — a rule that leaves a residue of "and these ones because they feel important" is a summary
wearing a criterion's clothes.

**It is what makes the two obvious cases come out differently.** The JavaScript rule can leave,
because a session about to write JavaScript reaches the vault first and `/pre-task` enumerates the
constraint by itself ([[the-javascript-rule-leaves-claude-md-and-is-not-yet-removed]]). The
test-database rule stays, because running the suite against the production database is not
recoverable by asking afterwards ([[the-suite-never-runs-against-the-production-database]]).

## What it does not settle

**"What will always be in `CLAUDE.md`" is owed its own record — deferred, 2026-08-18.** The owner
asked for it to be written down separately and it was not discussed in detail, so nothing here
enumerates the set; this page carries only the test a candidate is put through. The file's own state
is [[the-repository-claude-md-after-the-rules-left-it]], and where it is going is
[[the-repository-claude-md-becomes-a-dispatch-table]].

**And membership is not decided by how often a rule is asked for**: a frequency cache was
refused on the same day, with the statistics approved for collection anyway
([[no-frequency-cache-for-claude-md]]).

**Consequence of leaving it deferred:** each rule that is proposed for removal argues the criterion
again from scratch, which is what this page reduces and does not remove.

# The criterion was changed rather than exempted — owner, 2026-08-20

> **owner:** «hook добавляем, регион в `CLAUDE.md` убираем. Я принимаю этот риск.»

**`/pre-task` left this file, and it is the rule that bootstraps the asking.** The librarian raised
this page at the pre-task run for that work; the owner ruled anyway, on the ground that **delivery
which is reliably ignored is not delivery** — the rule was arriving in every session and was skipped
three times in two sessions
([[pre-task-was-skipped-again-and-the-record-is-a-recurrence-rather-than-an-incident]]).

**The session's own words for it, and the owner's: this is a change to the criterion, not a case
exempted from it.** The distinction is load-bearing. An exemption leaves the criterion able to sort
the next rule; a change means the first half — *what bootstraps the asking* — now yields where
unconditional delivery has been demonstrated not to work.

**What this page still sorts without a remainder is untested since.** The property that made it a
criterion rather than a taste was that it sorted all nine rules of that file; it has since been
applied in opposite directions on one day, and both applications are recorded
([[a-rule-applied-in-opposite-directions-on-one-day-is-not-a-reversal]],
[[the-pre-task-rule-leaves-claude-md-for-a-hook-message]],
[[dispatch-librarians-in-parallel-only-for-reading]]).

**Nothing here revises the criterion's text**, and re-reading it is the owner's
([[the-librarian-writes-unattended]]).

# CORE is the owner's alone to define, and the list emerges — owner, 2026-08-21

> «CORE определяется только мной. В процессе разработки мы придем к конкретному списку.»

**A session may not decide what is core, and may not derive it from a test.** The session of
2026-08-21 proposed an admission test for the core set — the shape it had just built for pages —
**and it was not adopted**. The criterion above stands as *his* criterion; what is refused is any
mechanism that would answer the question in his place
([[occams-razor-is-the-ground-rule-for-the-vault]]).

**And the list is expected to arrive by development rather than by drafting**, which is why the
absence of a written list is not a gap to be filled by whoever notices it first.

# The criterion is run on a trigger rather than on a schedule — 2026-08-26

*(the owner selected it, against keeping a periodic check.)*

**The criterion is applied when somebody proposes to add a rule to `CLAUDE.md` or to take one out**,
and at no other time. It stops being a standing debt.

**The measurement that decided it: the periodic check was never performed once in eight sessions.**
A recurring obligation nobody performs is an obligation that costs a line in every plan and produces
nothing ([[a-deferred-check-must-be-run-when-its-condition-arrives]]).

**And the trigger is where the criterion is actually needed.** Its whole job is to answer *does this
rule belong in the file that arrives unconditionally* — which is a question only asked when the file
is about to change.

**Confirmed after it was explained in plain language**, which is the shape the owner asks for when a
recommendation turns on a distinction.
