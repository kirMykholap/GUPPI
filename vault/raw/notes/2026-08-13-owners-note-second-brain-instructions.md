# Project Librarian: LLM Wiki Configuration

## 🎯 Purpose
Этот Vault является «скомпилированной» базой знаний проекта. 
Claude Code выступает в роли библиотекаря: он перерабатывает сырые отчеты (handoffs) в структурированную сеть атомарных знаний. 
Цель — накопление контекста, исключение противоречий и подготовка базы для эффективной работы агентов-разработчиков [2, 8-11].

## 📁 Directory Layout
- **raw/handoffs/**: Исходные отчеты в конце сессий/спринтов (immutable) [7, 12-14].
- **wiki/**: Сгенерированные знания (только для записи агентом) [7, 12, 14, 15].
  - **wiki/entities/**: Описания модулей, компонентов и сущностей системы [14, 16, 17].
  - **wiki/decisions/**: Реестр принятых архитектурных и проектных решений [14, 16, 17].
  - **wiki/tasks/**: Статус и детализация задач текущего и прошлых спринтов [18].
- **wiki/index.md**: Автоматически обновляемый каталог всех страниц [16, 18-21].
- **log.md**: Хронологический журнал действий библиотекаря [16, 18, 20-22].
- **archive/**: Место для устаревших (deprecated) сущностей и завершенных handoffs [18, 21, 23].

## 📜 Conventions & Schema
1. **Атомарность**: Одна сущность или одно решение = один файл [14, 24].
2. **Именование**: `[category]-[short-description].md` (lowercase, kebab-case) [7, 25, 26].
3. **YAML Frontmatter**: Обязателен для всех файлов в `wiki/`:
   ```yaml
   title: "Название"
   type: entity | decision | task
   status: active | deprecated
   created: YYYY-MM-DD
   sources: ["[[handoff-filename]]"]
   ``` [17, 27-30]
4. **Ссылки**: Использовать `[[wikilinks]]` для связей между страницами [23, 27, 28, 31].
5. **Противоречия**: При обнаружении конфликтов с ранее записанными данными использовать блок `> [!CAUTION] CONTRADICTION` и запрашивать уточнение у пользователя [9, 27, 32, 33].

## 🛠 Workflows (Custom Skills)

### 📥 /ingest
**Триггер**: Ручной запуск при появлении нового handoff в `raw/handoffs/`.
**Процесс**:
1. Прочитать новый handoff (строгий шаблон) [23, 26, 34, 35].
2. Обновить соответствующие файлы в `wiki/`. 
3. Если решение в handoff отменяет старое: переместить старый файл в `archive/`, сменить статус на `deprecated`, добавить ссылку на новое решение [23, 27, 33, 36].
4. Обновить `wiki/index.md` и добавить запись в `log.md` [18, 20, 23, 26, 34].

### 🔍 /lint
**Триггер**: Ручной запуск в конце спринта [2, 33, 36, 37].
**Процесс**: 
- Найти "осиротевшие" файлы (без ссылок) [27, 33, 36, 38].
- Проверить актуальность `status: active` для всех решений [33, 36, 38].
- Сверить текущую архитектуру в `wiki/entities/` с реестром `wiki/decisions/` [32].

### 🚀 /pre-task
**Триггер**: Перед началом любой новой задачи агентом-разработчиком.
**Процесс**: 
- Агент обязан прочитать `wiki/index.md` и все `active` файлы в `wiki/decisions/`, чтобы убедиться, что его план не противоречит принятым стандартам проекта [20, 27, 39].

## 📦 Sprint Closure
По завершении ретроспективы:
1. Выполнить финальный `/ingest`.
2. Переместить файлы текущего спринта из `raw/handoffs/` в `archive/sprints/sprint-N/` [23, 29].
