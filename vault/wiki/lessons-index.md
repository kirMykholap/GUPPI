lesson-agents-at-import-not-expanded: an `@path` in an agent definition is passed to the subagent as literal text, unlike the imports of CLAUDE.md and the `@` lines of a skill; the agent must Read the file itself, one extra tool call per dispatch, and the index text lands in its context, not the caller's
lesson-agents-loaded-at-session-start: Claude Code reads agent definitions at session start and skills on demand; a rendered agent is usable only from the next session, so an Estimate on a new agent cannot be read in the session that creates it
lesson-estimates-criterion-stale-after-contract-change: a decision update on a Rule page has no step that lists the Estimates whose criterion quotes the changed wording; until lint or the generator does it, the acknowledging reply must grep estimates/ for the words the contract dropped
lesson-hooks-exitplanmode-payload: `tool_input` is `{}`; the plan text is in `tool_response.plan`, whole, with `session_id`, `transcript_path`, `cwd` and `permission_mode` beside it, so C9 (copying the approved plan into `raw/<date>/spec.md`) can be a hook
lesson-hooks-messagedisplay-cannot-block: `MessageDisplay` can neither block nor add context, which is why the ledger writer lives on `Stop`
lesson-hooks-sessionstart-cannot-block: `SessionStart` cannot block — exit 2 is a no-op there — so gating belongs on `PreToolUse`
lesson-hooks-stop-payload: the payload carries `last_assistant_message` with the whole reply text, `stop_hook_active` (false on an ordinary stop), `session_id`, `transcript_path`, `cwd`, `permission_mode`; a `Stop` registration added to `settings.json` fired at the end of the same turn, no restart needed
lesson-hooks-windows-stdin-encoding: a hook's stdin on Windows is a cp1252 text wrapper with `surrogateescape`; a UTF-8 payload becomes lone surrogates, `write_text(encoding="utf-8")` raises after creating the file; fixed by reading `stdin.buffer` and decoding UTF-8 (`read_text` in `guppi/event.py`), stderr reconfigured to UTF-8 in `cli.py`, covered by tests
lesson-tests-cli-date-pinned: the test helpers wrote the event log under a pinned TODAY of 2026-09-09 while cli.main reads the real clock, so the tests passed only on the day they were written; the three CLI tests now pass the local clock's date to the helpers
