## Purpose

Prevents a Case from being shown to the person in a form the checks of pre-spec refuse, or with other `given`, `when`, `then`, `tasks` or `ratification` than the ones that passed them, while fewer than three refusals of that Case stand since the person's last message, a round of `case-guppi` from reaching the main agent with a question out of the form of the template of `.claude/skills/grill-me/SKILL.md`, a round of `case-guppi` from being shown after a text of the main agent's own written after the round came back with no word to the agent: the `Stop` run lets the showing through, and the run on `UserPromptSubmit` tells the agent of it at the person's next message, so that the round is not shown twice, and a Case from being shown with a text of the main agent's own outside the list under its heading and its `ratification` or written after the summary of `case-guppi` came back with no word to the agent, told in the same way at the person's next message, so that the Case is not shown twice, while a Case whose file was not sent or whose showing differs from the stored text is still refused, each judged only by what follows the last refusal of the check in the turn, and a summary of `case-guppi` from reaching the main agent without the id and the name of the Case it built; the Case reaches the person in the file `case-guppi` writes, which the hook checks whole when the agent stops and stores, and a file that differs from its stored text is not shown or written into the Spec. The hook takes as a file of a Case only a file named `case-<N>.md` under `cases/`, so the working note `note-<N>.md` that `case-guppi` keeps beside its Case is not checked, stored or sent back. The check of the file of a Case compares its Cases with the other Cases of the session, ratified or not, a dropped Case whose file is empty and a stored Case that the file of its top-level Case no longer holds aside, by the judgment the check after ratification runs, so a Case that writes what another Case writes goes back to `case-guppi` before the person first sees it; a Case that a `{supersedes:case N}` mark on a decision line of the file itself names is no such other Case, so a Case built again under a new number passes the check while the build it replaces stands in the plan. A Case of the plan that was built again after its ratification, whose entry in the store holds no finding and whose top-level file still holds it, is taken as the store holds it, in place of the plan, in each judgment that reads the other Cases, so that the words its pairs wrote are judged, and looked for in a read of its file, as the person will ratify them. The check of the file of a Case also applies the `replace` and `reword` pairs of the other Cases of the session first and those of the file last, to copies of the pages in memory by `check_pairs` of `.guppi/guppi/prespec.py`, so an old text that a Case of the session already rewrote, or that then matches twice, goes back to `case-guppi` before the person approves the Case, not at `/pre-spec`. The hook of `rule-spec-write` checks a Case only after the person signed it. When a pair of the file changes a sentence into which a pair of another Case of the session wrote, the check sends `case-guppi` a note once that names the other Case, the page and the sentence, so the two new texts are read side by side before the person sees the Case. It sends `case-guppi` a note once, too, for each `update` of a page that the cascade of `.guppi/guppi/generate.py` archives after an item of the same file or of another Case of the session — a lesson of an Insight set `actioned`, an `open` Insight left with no live child, the Decision page of a superseded Case — by the judgment that `/pre-spec` prints as a `note:` line, so that the Case drops the update or its `context` says why it stands. It sends `case-guppi` a note once, too, for each file under `vault/wiki/`, `.claude/`, `.guppi/guppi/` and `.guppi/tests/` that holds a name of a page the file of a Case updates or deletes, or of a file of the repository outside `vault/wiki/` whose path the first code span of a task line of the Case writes, and that the subagent read by no `Read` call of the file and no `Grep` call whose `path` is the file: the names of a page are its slug, the file name of each path of its `governs`, `implementation_ref` and `code_ref`, the name of the agent, or of the skill with its slash, whose file those paths name, and `guppi <command>` for each command that `COMMANDS` of `.guppi/guppi/cli.py` maps to a module of those paths, and the names of a file are its file name and the name of the agent, the skill or the command it carries; the note gives the path, the name it holds and, for a page, its `purpose`, `root_cause` or `pattern` line, leaves out the file of the page or the file itself, the Decision pages, `log.md` and `brief.md`, and asks `case-guppi` to read the file or to name it in `context` with the reason it stands, and a transcript the hook cannot read gives no such note. For a name that more than 20 of the files it searches hold, it sends one note in place of a note for each of those files, with the name and the count of the files, and asks `case-guppi` to search for the name and to name in `context` that search and why each file it does not enter stands; a file that holds a name that 20 or fewer of them hold is still noted alone for that name. The checks of a Case are the ones of pre-spec and of the Spec hook, imported, not copied ([[rule-one-judgment-one-implementation]]), but for the check of the read of its pairs set out below, the note of the files that name what a Case changes and the check of a tag that `vault/wiki/tags.md` does not hold set out at the end of this text, and every check of a round knows a round by one test and its title line by one pattern; the text of the story sections — `context`, `problem` and `recommend` — is not among them, only their presence, their order, the script of the name, `context` and `problem` of a Case, by the language finding of pre-spec, and the title of each item of `recommend` against the questions of the rounds: the person judges the text. The check of the read of its pairs is the hook's own, since only the hook reads the record of the calls of `case-guppi`: a pair whose sentence around a match came back whole from no `Read` call on the page file, or, for the words that another Case's pair wrote into it, on the file of that Case, goes back to `case-guppi`, and the output of a search is no read, so that no pair is signed from the line a search printed. The `Stop` run judges every reply whether `stop_hook_active` is set or not, since Claude Code keeps the flag set from a refusal of any `Stop` hook until the person's next message, and guards its own loop by its refusals in the transcript since that message: a reason of one Case is given at most three times, and a showing still wrong after that passes with a line on stderr, the Spec hook comparing it at ratification. The check of the file of a Case also sends back a Case whose `create`, `set` of `tags` in an `update` or decision line carries a tag that no row of `vault/wiki/tags.md` holds and that no tag line of the same file, or of a Case of the session with a decision line in the session's ledger, declares, so that an unlisted tag reaches no page through a Case; with no `tags.md` no tag is judged, and the rows are read by `.guppi/guppi/tags.py`, the one reading that `.guppi/guppi/ledger.py` and `.guppi/guppi/generate.py` share. The check also sends back, once for each text, an answer of `case-guppi` that wrote a file of a Case, that is no round, no `**Fact:**` answer and no `**Dropped:**` answer, and that holds a line opening with `**Built:**` after a first line of other text, so that `case-guppi` answers again with the summary alone, its first line `**Built:**`.
