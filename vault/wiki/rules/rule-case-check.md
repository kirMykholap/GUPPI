## Purpose

Prevents a Case from being shown to the person in a form the checks of pre-spec refuse, or with other `given`, `when`, `then`, `tasks` or `ratification` than the ones that passed them, while fewer than three refusals of that Case stand since the person's last message, a round of `case-guppi` from reaching the main agent with a question out of the form of the template of `.claude/skills/grill-me/SKILL.md`, a round of `case-guppi` from being shown after a text of the main agent's own written after the round came back with no word to the agent: the `Stop` run lets the showing through, and the run on `UserPromptSubmit` tells the agent of it at the person's next message, so that the round is not shown twice, and a Case from being shown with a text of the main agent's own outside the list under its heading and its `ratification` or written after the summary of `case-guppi` came back with no word to the agent, told in the same way at the person's next message, so that the Case is not shown twice, while a Case whose file was not sent or whose showing differs from the stored text is still refused, each judged only by what follows the last refusal of the check in the turn, and a summary of `case-guppi` from reaching the main agent without the id and the name of the Case it built; the Case reaches the person in the file `case-guppi` writes, which the hook checks whole when the agent stops and stores, and a file that differs from its stored text is not shown or written into the Spec. The check of the file of a Case compares its Cases with the other Cases of the session, ratified or not, a dropped Case whose file is empty and a stored Case that the file of its top-level Case no longer holds aside, by the judgment the check after ratification runs, so a Case that writes what another Case writes goes back to `case-guppi` before the person first sees it; a Case that a `{supersedes:case N}` mark on a decision line of the file itself names is no such other Case, so a Case built again under a new number passes the check while the build it replaces stands in the plan. The check of the file of a Case also applies the `replace` and `reword` pairs of the other Cases of the session first and those of the file last, to copies of the pages in memory by `check_pairs` of `guppi/prespec.py`, so an old text that a Case of the session already rewrote, or that then matches twice, goes back to `case-guppi` before the person approves the Case, not at `/pre-spec`. The hook of `rule-spec-write` checks a Case only after the person signed it. When a pair of the file changes a sentence into which a pair of another Case of the session wrote, the check sends `case-guppi` a note once that names the other Case, the page and the sentence, so the two new texts are read side by side before the person sees the Case. It sends `case-guppi` a note once, too, for each `update` of a page that the cascade of `guppi/generate.py` archives after an item of the same file or of another Case of the session — a lesson of an Insight set `actioned`, an `open` Insight left with no live child, the Decision page of a superseded Case — by the judgment that `/pre-spec` prints as a `note:` line, so that the Case drops the update or its `context` says why it stands. The checks of a Case are the ones of pre-spec and of the Spec hook, imported, not copied ([[rule-one-judgment-one-implementation]]), but for the check of the read of its pairs set out below and the check of a tag that `vault/wiki/tags.md` does not hold set out at the end of this text, and every check of a round knows a round by one test and its title line by one pattern; the text of the story sections — `context`, `problem` and `recommend` — is not among them, only their presence, their order, the script of the name, `context` and `problem` of a Case, by the language finding of pre-spec, and the title of each item of `recommend` against the questions of the rounds: the person judges the text. The check of the read of its pairs is the hook's own, since only the hook reads the record of the calls of `case-guppi`: a pair whose sentence around a match came back whole from no `Read` call on the page file, or, for the words that another Case's pair wrote into it, on the file of that Case, goes back to `case-guppi`, and the output of a search is no read, so that no pair is signed from the line a search printed. The `Stop` run judges every reply whether `stop_hook_active` is set or not, since Claude Code keeps the flag set from a refusal of any `Stop` hook until the person's next message, and guards its own loop by its refusals in the transcript since that message: a reason of one Case is given at most three times, and a showing still wrong after that passes with a line on stderr, the Spec hook comparing it at ratification. The check of the file of a Case also sends back a Case whose `create`, `set` of `tags` in an `update` or decision line carries a tag that no row of `vault/wiki/tags.md` holds and that no tag line of the same file, or of a Case of the session with a decision line in the session's ledger, declares, so that an unlisted tag reaches no page through a Case; with no `tags.md` no tag is judged, and the rows are read by `guppi/tags.py`, the one reading that `guppi/ledger.py` and `guppi/generate.py` share.
