## Purpose

Prevents a reference to a case, a mention of a session of this repository or a page that stays in this repository from reaching the clean version of GUPPI that other people install. `guppi ship` builds that version from the working tree into an empty folder: `.guppi/`, which holds the package `guppi` with its `pyproject.toml`, `uv.lock` and `.gitignore`, with its tests `.guppi/tests/` but `.guppi/tests/test_ship.py`, the tests of the command `ship`, and not its Python environment `.guppi/.venv/`; `.claude/`, `CLAUDE.md`, `.gitattributes`, the `schema.yaml` of each category, `vault/wiki/tags.md`, each page with `core: true` and each file rendered from such a page, but `sprint.md`, `backlog.md` and `guppi.toml`, which belong to this project, and the `pyproject.toml` and `uv.lock` at the root of this repository, which [[rule-guppi-package]] keeps for the development of GUPPI. It writes each file under `plugin/skills/` of this repository to the same path under `skills/` of the clean version, where Claude Code finds the skills of a plugin, and judges and cleans it like each other file it writes, and `guppi ship --check` judges each file under `plugin/skills/` in place; the one such file is `plugin/skills/install/SKILL.md`, which the Render of [[rule-plugin-install]] writes (case 818). In place of the session files of this project it writes skeletons, so the first `/hi` of a project that installs GUPPI finds each file it loads: `vault/wiki/sprint.md` in the closed form of the sprint `guppi`, so that `/hi` starts `/sprint-open`; `vault/wiki/backlog.md` and `vault/wiki/glossary.md` as `guppi backlog` and `guppi glossary` write them over the clean version; a `vault/wiki/brief.md` whose Next session opens its Cases with the line that opens the next sprint; and a `vault/wiki/log.md` that holds its heading alone (case 822). It gives each page `origin: guppi`, `sprint: guppi`, the date of the run in `created` and a `## History` of one line, and keeps in its link fields only the pages it writes. It also writes the folder `.claude-plugin/`, which makes the clean version a Claude Code plugin and the catalogue that lists it: `plugin.json`, the manifest of the plugin `guppi`, and `marketplace.json`, the catalogue `guppi-marketplace` of the owner `kirMykholap`, whose one entry is the plugin `guppi` at the root of the branch, `./`. It copies both from the folder `plugin/` of this repository, which no branch of this repository loads as a plugin and which the clean version does not hold (case 816). It also writes each `passed` Estimate whose target page it writes, with `core: true` written into its copy and a `## Result` of one line, the date of its last reading and that it passed in the repository of GUPPI; no Estimate of this repository carries `core`, an Estimate that is `pending` or `failed` stays here until its reading passes, and one whose `method` names a target of the `Makefile` stays here until a Case moves it to pytest (case 822).

A pointer — a reference to a case, an id `decision-case-N` or a mention of a session by its id — stands in this repository in a bracket of its own at the end of its sentence, together with the words that go with it, such as `(as set in case 12)` or `(measured 2026-09-25, session 0051)`, so that the sentence reads whole without it. `guppi ship` removes each bracket that holds a pointer whole, every word in it included, and each `[[decision-case-N]]` link; a bracket that holds no pointer stays. A case number with no word `case` or `cases` before it, such as `(274.1)`, is no form of a pointer, and `guppi ship` does not remove it; in a comment or a docstring of a Python file it exits 1 on each bracket that holds only case numbers, on each comment or docstring that opens with one or more case numbers, joined as in such a bracket, followed by a colon, and on each comment whose whole text is one or more case numbers joined the same way, and it judges no code outside them. In a test file under `.guppi/tests/` it cleans and judges only the comments and the docstrings: each other string is a sample, as a code span of a page is, so a case id in the data of a test is neither removed nor judged (case 822). It writes any other `[[…]]` link to a page or a file it does not write as the slug in a code span. In the Render of `rule-claude-md` and in `CLAUDE.md` that it writes, it puts the heading `# Project` and the line `Project description: not set yet.` between the lines `<!-- project-description -->` and `<!-- /project-description -->`, in place of the heading and the description of GUPPI, which the install Case of `rule-morph` replaces with the description of the project (case 822). A case id in a code span or a fenced block, of a Markdown file or of the text of a `schema.yaml`, or in the form of a line after `[case `, `#case-` or `:case `, is no pointer; the example Case of `case-example.md` and of the Render of `rule-case-example` stands in a fenced block, and the text around it is judged and cleaned like the text of any other page. It exits 1 on each pointer that stands outside such a bracket, and on each section of a page without `core: true`; a Case rewords that text at its source. It does not write `.guppi/guppi/ship.py`, so a project that installs GUPPI, which builds no clean version, gets no command `ship`, and `guppi check` skips its step `guppi ship --check` there; the judgment of a pointer outside its bracket, which `guppi ship` and `/pre-spec` share, lives in `.guppi/guppi/pointers.py`, which it writes (case 820). `guppi ship --review` also lists each bracket it removes that holds words beside its pointer, so that a word the sentence needs is found and moved out of the bracket. `guppi ship --check` judges in place each file outside `vault/` that the clean version holds — the code, the harness and the files at the root of the project — and `uv run --project .guppi guppi check` runs it; `/pre-spec` finds a pointer outside such a bracket in the new text of a page with `core: true` before the Spec is approved, or, for a Case ratified in Work Mode, before its tasks run (case 807).

The workflow `.github/workflows/prod.yml` runs it on each push to `main`, and on each push of a tag `prod-*` on a commit of another branch. `guppi ship <folder>` gives `.claude-plugin/plugin.json` the version of the highest tag `prod-x.y.z` in the history of the commit it builds, such as `0.2.0` for the tag `prod-0.2.0`; a tag of another form, such as `prod-2`, gives no version, and when no tag `prod-x.y.z` stands in that history `guppi ship <folder>` exits 1 and writes nothing, so the run writes nothing to `prod`; `guppi ship --check` reads no tag (case 816). While a rule or an entity with `core: true` stands `draft`, `guppi ship <folder>` prints one line for each such page, writes nothing and exits 1, so the workflow writes nothing to `prod`; with the option `--allow-draft` it writes the clean version into the folder all the same and prints those lines, which set no exit code, for an install by hand from that folder, which is where a check that needs an install reads it, and the workflow never passes that option. `guppi ship --check` does not judge the status of a page, and `guppi lint` reports each such page where the module of the command `ship` stands; both judge it by `is_draft_core` of `.guppi/guppi/pages.py`. A draft page that a new project can go without loses `core` until it is `built` (case 822). It writes the result to the branch `prod` as one new commit on top of the last, whose message names the commit it was built from, and writes none when nothing changed or when the command exits 1. Before it commits, it installs Claude Code and runs `claude plugin validate` on the clean folder, and writes nothing when that check fails (case 816). It pushes with a deploy key of this repository with write access, whose private half is the repository secret `PROD_DEPLOY_KEY`; deploy keys stand on the bypass list of the ruleset on `prod` that [[rule-github-repository]] sets. This rule and the workflow belong to this repository: neither carries `core`. Of `.github/` the clean version holds only `.github/workflows/checks.yml`, the CI that runs the tests, the vault checks and the style check of a project, judged and cleaned like each other file it writes, and `guppi ship --check` judges it in place (cases 804, 822).
