## Purpose

Prevents a ratified Case from entering the Spec in other words than the Case `case-guppi` wrote into its file, whose `given`, `when`, `then`, `tasks` and `ratification` the person signed and the check of `rule-case-check` stored. `case-guppi` writes the whole Case in English, and a hook copies its stored answer.

## How it works

`uv run guppi ratified` on `Stop`. After a reply whose `LEDGER` block holds `- decision[case N]` lines of a kind other than `defer`, it reads `<plan>.checked.json` for the text of the file of `case-guppi` stored under Case N by `rule-case-check`, and the session's transcript for a `SendUserFile` call on `raw/<date>/<hi HHMM>/cases/case-<N>.md`, N the id of the top-level Case, and for the last earlier reply that shows Case N with a section; no such call made after the time of the store, a file of Case N whose Cases differ from the text the store holds under their ids or that the store does not hold, by the one comparison of `guppi/casecheck.py` that the `Stop` check of a showing runs, a showing that differs from that stored text in a section it shows — by the one comparison of `guppi/casecheck.py` on `Stop`, imported with its reading of a sending — a store with no Case N, or a Case N stored with findings is a refusal, exit 2, and nothing of Case N is written; otherwise it writes the stored answer of Case N into the plan file named by `plan_path` of the ledger module, outside the repository: the heading, `context`, `problem`, `recommend`, `given`, `when` and `then` as they stand — a sub-case's own `recommend` under its heading — a block tagged `then` built from the sub-points of `tasks`, and a block tagged `tasks` of the task lines without their sub-points, each opened and closed by a fence of backticks one longer than the longest run of backticks that opens a line inside it, three at the least; the section of Case N is replaced when it stands, appended otherwise. Once `spec.md` in the session's folder stands, the hook writes the same stored answer into it too: every section of Case N there replaced, or the Case placed after its family, before the `## Deferred` of the last approved document, or at the end; a task line whose text stood in a replaced section keeps its box; the `context`, `problem` and `recommend` of a sub-case's parent come from the parent's stored answer, never from the reply. After the write it runs the checks of `prespec --check`, imported from `guppi/prespec.py`, on each Case it wrote, with the decision lines of the reply added to those of the session's ledger — the ledger hook runs in parallel on the same `Stop` — and without the Frontier, the translation and the grammar of the ledger, which stay with `/pre-spec`; on a finding it exits 2 with the findings on stderr, each naming its Case, and the written Case stays. No plan file, or a sub-point it cannot read — a value holding a backtick whose outer span is not padded by one space on each side among them: exit 2 with the reason on stderr. A sub-point that reads into no key `item_keys` of `guppi/materialize.py` gives its item — `slug` a key of every kind; the one judgment `materialize` lifts by and `generate` applies by — is refused the same way: exit 2, and nothing of the Case is written. A task line that opens with `tag` and the tag in its first code span declares a new tag: its sub-points `meaning` and `aliases`, each one code span, make one entry of `new_tags` in the block tagged `then`, which `guppi materialize` carries to `guppi generate`, and the line stands in no block tagged `tasks`, since it is no task; a tag line with either sub-point missing, with another sub-point or with a value that is not one code span is refused, exit 2, and nothing of the Case is written. A `create` or a `defer` of a category with no schema file, or of one whose schema rule a decision line of the session or of the reply creates or updates, is not judged by its keys. A defer-only Case — a Case whose lines in the reply are all `defer`, beside other Cases or alone — is written by the same hook from the reply that carries its lines and shows it in the short form — `context`, `problem`, a fence tagged `then` — under `## Deferred` of the plan file, or of `spec.md` in the session's folder once that file stands; the check after the write does not run on it; a key of a `defer` item that `item_keys` of `guppi/materialize.py` does not give a `defer` of its category is refused, exit 2, and nothing of the Case is written; so is a `then` block that holds a YAML comment — a `#` at the start of a line or after a space or a tab, outside a quoted value and outside a `|` or `>` block — by the one function of `guppi/materialize.py`, since after a space YAML drops the rest of the line and no page receives it, and after a tab PyYAML, the library the scripts use, refuses the whole block. After the writes, a decision line of the reply that carries `{supersedes:case N}`, its own Case written in this run, removes the section of Case N — with its sub-cases, or `### Case N.M` alone when the line names a sub-case, and then its parent too once the marks of the session's ledger and of the reply retire each sub-case of that parent with a decision line, by `retired_whole` of `guppi/prespec.py`, and the parent holds no decision line of its own that no mark retires — from the plan file and, once it stands, `spec.md` in the session's folder, under `## Deferred` too; a Case N none of them holds is no refusal. An error of the hook itself after it has read the payload — an exception while it reads the transcript, the store, the plan file or `spec.md`, or writes, removes or checks a Case — exits 2 with `ratified: not done: <error>` and the advice to repeat the ledger lines once the cause is fixed on stderr, so the agent sees it at the end of that reply, unless the same line already stands in a refusal of its own in the stretch, and with `stop_hook_active` set and a transcript it cannot read it exits 0 and prints nothing; a Case not yet written is written at the reply that repeats its lines, and one written before the error stays and is replaced then. An error while it reads the payload exits 0 with the error on stderr, since the hook cannot read its refusals then; the guard of `rule-spec-reconcile` keeps exit 0 on its own error. The hook writes, removes and checks whether `stop_hook_active` is set or not: Claude Code keeps the flag set from the first refusal of any `Stop` hook until the person's next message, so a Case whose ledger lines a reply repeats after a refusal would otherwise wait for the person to write again. It guards its own loop by its refusals in the stretch, the transcript after the person's last message, read by `own_refusals` of `guppi/ledger.py`: a reason that already stands in one of them is not printed again, by `untold` of the same module; the hook exits 2 only while a reason not yet given is left, and with the flag set and a transcript it cannot read it prints nothing and exits 0.
